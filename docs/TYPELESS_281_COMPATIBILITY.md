# Typeless 2.8.1 兼容验证

日期：2026-10-06，macOS / Apple Silicon。官方安装版本为 2.8.1（2.8.1.130）。
基线为已合并 PR #10 的主分支提交 `4f64e73`。

## 首次适配与候选验证（PR #11）

- 当前会话仍能按原格式读取，官方账户页显示已登录；接口却返回 HTTP 403，并明确说明
  不支持第三方客户端。已区分 401 登录失效、普通 403 和该固定拒绝响应。不复刻客户端
  安全签名，不刷新或注入会话，不修改官方应用或存储。
- 明确拒绝第三方客户端后，停止同一会话的事件重试。手动刷新或会话变化可按冷却规则
  重新查询。只回退到仍在运行的官方客户端、已确认身份、新鲜且来源为 Accessibility 的
  周额度；本地猜测、待核对、需要重启、过期快照和其他鉴权失败不能启用该回退。
- 官方 2.8.1 账户页把账户、邮箱和订阅合并成一个文本节点。新增识别仍要求官方 hub 文档
  和真实账户、设置、退出按钮，拒绝历史文本、其他文档及互相冲突的身份。换号后的重启
  隔离规则继续生效。
- 版本读取直接读取安装包 Info.plist，避免常驻管理器因 Bundle 缓存长期显示旧版。
- 官方首页可见额度为 106 / 2,000；额度上限取自实际来源，没有写死旧版的 8,000。

## 使用与范围

遇到第三方接口限制后，根据应用提示结束录音、正常重启 Typeless，打开设置 → 账户核对
邮箱，再回主页读取额度。若官方主窗口没有暴露可读的 AX 内容，继续显示未知；不会用
旧主页数字填补缺口。活动状态未知时，自动守护仍暂停切换。

此变更是源码与本地候选验证，不代表正式发布、公证、更新 feed 推送或已安装应用升级。

## 合并后的本机验收

PR #11 已合并为 `df3824a`，随后在现有账号上安装并正常重启官方客户端。此时发现
`AXWindows` 仅列出浮条，但 `AXMainWindow` / `AXFocusedWindow` 能返回官方 hub 主窗口。
只使用前一个入口仍会漏掉账户页和首页额度；现在合并这些窗口入口并按 AX 身份去重，
额度读取器与界面事件观察使用相同枚举结果。

- 窗口遗漏回归先 RED：4 项测试中 3 项失败、6 个断言失败；修复后通过。
- 显示官方账户页时的 opt-in 只读实测先失败（未读到 hub 与身份），修复后通过；输出
  只含能力布尔值与脱敏标签。
- `make verify` 通过：210 项 Swift 测试，204 通过、6 项 opt-in 默认跳过；8 项 Python
  校验、应用包、签名、隔离迁移与 feed 校验通过。
- 已用同一 Developer ID 签名更新本机辅助应用，保留旧 app 备份和现有账号/偏好。
- 正常重启 Typeless → 账户核对 → 首页后，已安装辅助应用自动显示已用 `88 / 2,000`、
  剩余 `1,912`，与官方首页一致。持久化额度来源为 `typelessAccessibility`，快照新鲜，
  当前账号状态为 available；官方 API 限制提示仍如实显示。
- 脱敏诊断导出通过，确认官方版本 `2.8.1`、界面额度来源及新鲜状态。

录音/处理控件仍没有足够的 AX 状态证据，自动切换保持暂停。真实多账号切换/恢复、
服务器瞬时升级弹窗关闭与实际口述仍为 **UNVERIFIED**；没有为了验收创建账号或触发
录音。此本机安装不是新的公开 release、公证或更新 feed 发布。
